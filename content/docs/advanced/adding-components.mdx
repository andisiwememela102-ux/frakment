---
title: Adding a Component
description: Complete checklist when adding a new component to Frakment.
---

Follow every step. A component can install via the CLI and compile fine, yet stay invisible in the docs, sidebar, or changelog if any later step is missed. Three of those steps fail silently.

This guide assumes you already read the docs and changelog templates in [CONTRIBUTING.md](https://github.com/arrafipd/frakment/blob/main/CONTRIBUTING.md). If not, start there first.

## Prerequisites

- Local dev running (`npm run dev`)
- `npm ci` completed at least once
- Read the docs and changelog templates in `CONTRIBUTING.md`
- Know which category the component belongs to: `components`, `ai-elements`, `modules`, or `utilities`
## 1. Component source

Two files, identical content. The first ships via the CLI, the second lets you iterate locally without the CLI.

- `registry/<name>.tsx` — source that ships via `npx frakment add <name>`
- `components/ui/<name>.tsx` — mirror, used by local dev and examples

Keep them identical. `npm run registry:audit` fails if they diverge.

## 2. Registry entry

Add an entry to `frakment.json` under `components`. `dependencies` drives the `npm install` step when users add the component. `registryDependencies` drives auto-install of other Frakment components.

```json
{
  "name": "<name>",
  "title": "Component Name",
  "description": "One sentence.",
  "source": "registry/<name>.tsx",
  "target": "components/ui/<name>.tsx",
  "dependencies": ["class-variance-authority@^0.7.1"],
  "registryDependencies": ["button"],
  "type": "registry:ui"
}
```

Verify `dependencies` matches every external import in the source. Missing dep = broken install. Extra dep = unnecessary install. `registryDependencies` should match every `@/components/ui/<other>` import.

## 3. Examples

Create `examples/<name>-demo.tsx` with `"use client"` at the top. Add variants as separate files (`<name>-size.tsx`, `<name>-variant.tsx`) when useful.

Demo rules:

- Always `"use client"` if the demo uses state, events, or hooks
- Icons from `@/lib/icons`, not directly from `@phosphor-icons/react`
- Hardcoded props (demos are showcase, not tests)
- Root wrapper: `max-w-xs` for inputs, `max-w-sm` for forms, `max-w-md` for rich layouts
## 4. Docs page

Create `content/docs/{category}/<name>.mdx` where `{category}` is `components`, `ai-elements`, `modules`, or `utilities`.

Reference implementations:

- **Simple component**: `content/docs/components/button.mdx`
- **Composed module**: `content/docs/modules/questionnaire.mdx`
- **Utility**: `content/docs/utilities/shimmer.mdx`

Full template:

````mdx
---
title: "Component Name"
description: "One sentence: what it does and when to use it."
---

import { ComponentNameDemo } from "@/examples/component-name-demo";
````

The `<ComponentPreview>` `src` must point at the example file. Without it, the Code tab shows the component source instead of the usage example.
## 5. Sidebar and mobile nav

Add `"<name>"` to `content/docs/{category}/meta.json` under `pages`, alphabetically. Without this the page exists at its URL but is not linked from the sidebar, mobile nav, or command menu.

```json
{
  "title": "Components",
  "root": true,
  "pages": ["button", "card", "<name>"]
}
```

## 6. New badge

Add `"/docs/{category}/<name>"` to `PAGES_NEW` in `lib/docs.ts`. This drives the blue dot in the sidebar and mobile nav.

```ts
export const PAGES_NEW: ReadonlySet<string> = new Set([
  "/docs/components/<name>",
]);
```

`PAGES_NEW` is a **rotating batch**, not a cumulative list. When you ship a new batch, replace the entire set with only the components from that batch. Entries from the previous batch graduate and their dots disappear.

## 7. Changelog

Create `content/docs/changelog/YYYY-MM-DD.mdx` — one file per day, immutable after merge. Add the date to `content/docs/changelog/meta.json` under `pages`, newest first.

Reference `content/docs/changelog/2026-11-08.mdx` for a multi-entry batch. Template:

````mdx
---
title: "Month DD, YYYY"
description: "One sentence: what shipped."
date: "YYYY-MM-DD"
---

import { ComponentNameDemo } from "@/examples/component-name-demo";

One paragraph about the change and why it matters.

### Component Name

<ComponentPreview name="component-name" title="component-name-demo.tsx" src="examples/component-name-demo.tsx" previewClassName="h-auto py-8">
  <ComponentNameDemo />
</ComponentPreview>

One paragraph describing the component.

#### Installation

<Steps>
  <Step>Install</Step>

```bash
npx frakment add component-name
```
</Steps>

#### Minimal usage

```tsx
<ComponentName />
```

See the [Component Name docs](/docs/{category}/component-name) for the full API.
````

Rules:

- **Preview first.** Visual change → `<ComponentPreview>` above prose.
- **Code diff for non-visual.** CLI flags, config keys, dependency fixes → fenced code block.
- **Multiple entries per day** → `<hr className="my-16 border-border/40" />` between them.
- **Changelog only for user-facing changes.** Not docs typos, refactors, or internal tooling.
## 8. Build and verify

Run in this order:

```bash
npm run registry:build
npm run fix
npm run check
npm run typecheck
npm test
npm run build
```

`registry:build` regenerates `public/r/<name>.json`. Without it, `npx frakment add <name>` returns 404 for users even though the component works locally.

## 9. Silent failure checklist

These steps fail silently. The component installs, compiles, and works locally — but the CLI, sidebar, or changelog miss it.

| Missing | Symptom |
| :-- | :-- |
| `frakment.json` entry | `npx frakment add <name>` returns 404 |
| `meta.json` entry | Page exists at URL but is not in sidebar, mobile nav, or command menu |
| `PAGES_NEW` entry | Page is linked everywhere but without the new badge |
| `changelog/YYYY-MM-DD.mdx` + `changelog/meta.json` | Release does not appear in changelog |
| `npm run registry:build` not run | `public/r/<name>.json` is missing |

Before opening the PR, verify all five.

## PR checklist

- [ ] `registry/<name>.tsx` and `components/ui/<name>.tsx` are identical
- [ ] `frakment.json` entry has correct `dependencies` and `registryDependencies`
- [ ] `examples/<name>-demo.tsx` exists and renders
- [ ] `content/docs/{category}/<name>.mdx` follows the template
- [ ] `content/docs/{category}/meta.json` has the entry
- [ ] `PAGES_NEW` in `lib/docs.ts` has the entry (and only this batch)
- [ ] `content/docs/changelog/YYYY-MM-DD.mdx` exists and is linked from `changelog/meta.json`
- [ ] `npm run registry:build` ran and `public/r/<name>.json` is in the diff
- [ ] `npm run build` passes
- [ ] Commit is signed off (`git commit -s`)
